# Collaborative planner implementation contract

This is the shared implementation contract for the October 26 planner build.
Product: Planner replaces Profile in bottom navigation; Profile moves to a top-right avatar. Preserve Trotter paper/ink/photo design. No chat interface. Tiny right-side chevrons and net score for votes. Direct editing never invokes AI. Shared plans have a stable UUID independent of imported flight Trip rows. Personal Dreams are shared only by an explicit import or per-member future-save consent; choosing a destination alone never shares saves. New ideas/votes never rearrange an accepted plan.

- Root: App/nav/avatar integration, Dreams and capture integration, invitation deep links and public landing, deployment, integration/visual QA.

## HTTP contract (snake_case JSON)

All paths start `/planner`. All except invite preview require the existing auth dependency. Membership is checked on every read/write. Roles: `owner`, `editor`, `contributor`; contributors add ideas and vote, editors also edit plan, owner also manages people/access. IDs are strings (including serialized user IDs). Dates ISO `YYYY-MM-DD`; times destination-local `HH:mm`.

`TripSummary`: `{id,title,destination,start_date,end_date,timezone,pace,transport,transport_modes,role,version,member_count,idea_count,cover_image_url?,updated_at}`. Pace `relaxed|balanced|packed`; transport modes `walk|drive|transit`. `transport_modes` is a nonempty unique array (max3), and `transport` retains its first entry for legacy clients. Dates inclusive, max31 days. Unknown facts stay unknown.

`Idea`: `{id,title,category,city?,country?,image_url?,source_url?,google_place_id?,latitude?,longitude?,duration_minutes,must_do,score,my_vote,contributors:[{user_id,name}],source_count,created_by,status}`. my_vote is -1/0/1, status `ready|processing|needs_details`. Metadata copied from personal Dreams excludes private notes, raw captions and private email data. Only selected items are shared. Dedup confident place identity, never same-name different-city matches.

`Member`: `{user_id,name,role}`. `Invite`: `{id,label?,role,expires_at,status,uses}` (raw invite token never returned in lists). `Revision`: `{id,plan,source,created_at,base_version}`. `Job`: `{id,status,message?,revision_id?}` status `queued|running|completed|failed`.

`Plan`: `{days:[{date,stops:[Stop],stay?:Stay}],warnings:[string],unplaced_idea_ids:[string]}`.
`Stay`: `{status:'needed'|'suggested'|'selected'|'not_needed',idea_id?:string,city?:string,reason?:string}`. Stay IDs reference shared saved accommodation only. Selected means the user selected a stay, not that it is booked. Selected nights outside shortened dates are protected; accepted stay references cannot be deleted until removed from the plan. Alias resolution/history restore supports stay references.
`Stop`: `{id,idea_id?,title,start_time,duration_minutes,locked,kind,notes?,user_created?,generated?,travel_minutes?,travel_source?,travel_from_stop_id?,travel_mode?}`. kind `place|booking|break`; travel_source `google|estimate|unknown`; travel_mode is one of the trip's selected modes. `id` stable within manual edits. User-created breaks retain editable custom titles/notes even while unlocked; generated breaks are marked separately. Plan uses referenced idea identity, never invented venues. Preserve locked stops exactly when reworking. Accept/edit checks time validity, duplicate stops, idea ownership, date range, overlapping locked bookings. Unknown travel/opening data produces a truthful warning, not fabricated precision. Save/accept and accepted/draft reads recompute day-local predecessor travel from manual coordinates or the existing volatile coordinate cache only: no AI, paid routes, or hours requests. Display hydration copies plans and does not mutate immutable revision history.

`TripDetail` extends summary with `{ideas,members,invites,plan:Plan|null,draft:Revision|null,generation:Job|null}`. Every mutation below returns refreshed TripDetail unless specified otherwise. `expected_version` is required on plan/settings edits and destructive changes to prevent overwrites. Contributor votes/additions should not make unrelated manual edits impossible; implementation may separate plan revision concurrency from content updates while retaining API version semantics.

- `GET /trips` -> `{trips:TripSummary[]}`.
- `POST /trips` `{title,destination,start_date,end_date,timezone,pace,transport?,transport_modes?,client_request_id,dream_item_ids?:string[]}` -> TripDetail (idempotent creation). Explicit `transport_modes` is authoritative over the legacy field; omitted modes fall back to `[transport]`, default walk. Empty, duplicate, unknown or null mode arrays return422. Legacy create retries keep their original request fingerprint.
- `GET /trips/{id}` -> TripDetail.
- `PATCH /trips/{id}` `{expected_version,...changed_settings}` -> TripDetail. Explicit `transport_modes` updates the full array and legacy primary; a transport-only edit replaces the array with `[transport]`. Omitting both preserves the current selections. Existing accepted times/stays/notes remain unchanged; settings bump the version and invalidate stale drafts.
- `POST /trips/{id}/ideas/import` `{dream_item_ids:string[]}` -> TripDetail.
- `POST /trips/{id}/ideas` `{title,category?,city?,country?,source_url?,latitude?,longitude?,duration_minutes?,client_request_id}` -> TripDetail. Manual place entries are supported.
- `POST /trips/{id}/sources` `{source_url,shared_text?,client_request_id}` -> TripDetail. Explicitly capture a reel into this group using existing Dreams extraction; shared source associations must track all eventually parsed sibling places durably and enforce initiating member ownership. Root can help wire native capture target.
- `PATCH /trips/{id}/ideas/{idea_id}` `{duration_minutes?,must_do?,title?,city?,country?}` -> TripDetail, owner/editor or idea author as appropriate.
- `DELETE /trips/{id}/ideas/{idea_id}` -> TripDetail; prevent dangling accepted plan references or remove safely with explicit revision.
- `PUT /trips/{id}/ideas/{idea_id}/vote` `{value:-1|0|1}` -> TripDetail. One vote per person, change/clear supported, atomic uniqueness.
- `POST /trips/{id}/generate` `{expected_version,client_request_id,day?:YYYY-MM-DD,pace?:...,mode?:'ai'|'rules'}` -> Job, HTTP202. UI defaults ai; server controlled rollout/fallback truthful. Persist job before enqueue, recover lost dispatch/stale worker, no repeated paid calls on client retries. Bound per-user/trip generation usage; no AI on ordinary editing.
- `GET /trips/{id}/jobs/{job_id}` -> Job.
- `PUT /trips/{id}/plan` `{expected_version,plan}` -> TripDetail. Direct edits create accepted revision/history and never invoke AI.
- `POST /trips/{id}/draft/accept` `{expected_version,revision_id}` -> TripDetail. Reject incompatible stale drafts.
- `DELETE /trips/{id}/draft` `{expected_version}` -> TripDetail.
- `GET /trips/{id}/history` -> `{revisions:Revision[]}` (bounded).
- `POST /trips/{id}/restore` `{expected_version,revision_id}` -> TripDetail; restores as a new revision, does not erase history.
- `POST /trips/{id}/invites` `{role:'editor'|'contributor',label?,recipient_email?,client_request_id}` -> `{invite,share_url,token}`. Expiring, revocable, bounded-use tokens; no automatic messages sent.
- `DELETE /trips/{id}/invites/{invite_id}` -> TripDetail.
- `GET /invites/{token}` public -> `{trip:{id,title,destination,start_date,end_date,cover_image_url?},inviter_name,role,member_count,status}`; unavailable/expired/revoked errors clear, no membership/private source/email leakage.
- `POST /invites/{token}/accept` auth -> TripDetail. Explicit acceptance, idempotent, existing members are not downgraded. Email-bound invite acceptance verifies email.
- Prefer POST `/invites/resolve` `{token}` for public preview and POST `/invites/accept` `{token}` for acceptance. Keep raw tokens out of access-log paths. Share URL is backend `/planner/open#token=...`; native `trotterv2://planner-invite?token=...`; web `/#planner-invitation=...`. Root owns separate `routers/planner_landing.py`; backend agent registers it in main.py.
- `PATCH /trips/{id}/members/{user_id}` `{role:'editor'|'contributor'}` -> TripDetail (owner only).
- `DELETE /trips/{id}/members/{user_id}` -> TripDetail; owner cannot remove self without transfer, member may leave.

## Private matching and future saves (migration 0019)

All routes below require membership except the own-account destination catalog, which requires authentication. Choosing a matching scope is independent of the free-text display destination. The server matches exact normalized country/city values from categorized Dreams using existing aliases; no AI, substring matching, or provider calls are involved.

- `GET /dreams/destinations` → `{destinations:[{id,country,city:null|string,label,count}]}` from the current user's saves only. IDs are deterministic opaque SHA256 values; country-wide and city-within-country choices are separate. A custom trip without categorized matching saves remains valid with no scope.
- Create trip accepts optional `match_scope_id`; PATCH accepts it with `expected_version`, including explicit null to clear it. Only a scope from the editor's categorized saves is accepted (the already-selected scope can be retained). A changed scope clears **every member's** future-sharing consent. Plan/settings version advances once as usual. Changing the free-text title/destination never implicitly changes the scope.
- Summary/detail adds `match_scope:{id,country,city,label}|null` and `dream_sharing:{enabled,active,paused_reason,consented_at}` for the current member only. `paused_reason` is null, `no_destination`, `trip_ended`, or `access_removed`. Other members' preferences and private suggestion counts are never returned.
- `GET /trips/{id}/dream-suggestions?limit=20&cursor=<dream_item_id>` → `{scope,sharing,total,suggestions:[{dream_item_id,title,category,city,country,image_url}],next_cursor}`. Limit1–100; stable ascending item-ID pages. Total excludes that person's existing contributions and group removal tombstones; another member's matching place can still receive this member's contribution without creating a duplicate idea. Thumbnails use authenticated `/dream-items/{id}/thumbnail`. Private notes, captions, summaries and source metadata are excluded. Responses are private/no-store.
- `POST /trips/{id}/dream-suggestions/import` with `{scope_id,all:true}` **or** `{scope_id,dream_item_ids:[...]}` → TripDetail. All selected IDs must be owned by the caller and match scope. Maximum200 matching saves per request and200 active ideas per trip; overflow returns422 atomically. Retries are idempotent; imports never rearrange or version-bump the accepted plan. Bulk matching cannot resurrect deleted ideas.
- `PUT /trips/{id}/dream-sharing` `{scope_id,enabled:boolean}` → TripDetail. Default off, separate explicit consent for every person and trip. Enabling does not import existing saves. Re-enabling starts a fresh consent time. Scope mismatch returns409: `This trip's matching destination changed. Review it before sharing.` Removing/leaving a member clears their consent; trips pause after their destination-local end date.
- Future eligibility uses original source capture time (falling back to item creation), never extracted-sibling creation time when a source exists. A delayed categorization or delayed transaction commit of a genuinely future save remains pending until shared. An old private reel's newly parsed sibling remains a private suggestion.
- `app.services.planner_matching.reconcile_matching(db,trip,user_id=None,limit=100)` performs bounded, idempotent pending anti-joins and round-robin provider-identity refresh. Normal trip/suggestion reads run it for the current member; existing30-second `planner.discover_jobs` runs fair batches of50 consenting members,10 candidate/refresh records each, with trip locking. Definitely ended trips are excluded from discovery. No paid calls are made. Future additions change the shared idea pool only.
- Indexed canonical fields on Dreams are maintained on ORM insert/update and backfilled by frozen migration0019. Named identities preserve explicit neighborhood/branch evidence; conflicting confirmed Google IDs remain distinct. Deleted place identities remain suppressed across later provider resolution and repeated saves, without suppressing a different confirmed branch.

## Engine boundary

`generate_plan(payload: dict, *, use_ai: bool=True) -> dict` in planner_engine. payload `{trip:{id,title,destination,start_date,end_date,timezone,pace,transport},ideas:[Idea with factual fields],existing_plan:Plan|null,day?:str,pace?:str}`. Result `{plan:Plan,source:'ai'|'rules',usage:{input_tokens,output_tokens,cost_usd,model?}}`.

No DB/provider secrets in payload. Engine resolves permitted transient place facts using known IDs; never permanently copy Google names/addresses/hours/route content into arbitrary history. Use existing location retention policies; saved itinerary selections/times are app/user decisions. Clearly distinguish estimates. API service must strip volatile fact payloads before storage. AI bounded one request (at most one repair only if within cap), structured schema, IDs from provided candidates, no web search, no raw private notes or captions. Separate `PLANNER_AI_*` configuration; default Venice Kimi K2.5 candidate, no change to Dreams extraction. Deterministic validation and fallback, token cap including reasoning. Add deterministic planning baseline and tests comparing safety properties; live quality comparison is root-owned.
